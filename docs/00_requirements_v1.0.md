# 本科交互式线上实践课程：要求与实施方案（v1.0）

> **试点课程**：《室内空间设计》（住宅方向）  
> **试点实验**：90㎡三居室住宅的公共生活空间设计  
> **文档定位**：教学要求 + 产品定义 + 技术路线 + Agent 可执行任务书  
> **版本日期**：2026-10-19  
> **状态**：讨论方案；技术选型与教学效果尚待实测

---

## 0. 核心结论

本项目的主要目的**不是开发一款住宅设计软件，也不是把教材视频搬上网页**，而是借《室内空间设计》验证一个可以向其他本科实践课程复制的教学模式：

**知识理解 → 真实问题 → 自主设计决策 → 可视化结果 → 情境验证 → 解释与反馈 → 修订方案 → 学习迁移。**

交互操作必须为认知服务：拖动、旋转、替换家具可以是动作，但不能成为教学目标。最终验收既要看“能否操作”，更要看“学生是否理解设计因果关系，能否在新的问题中作出并解释设计判断”。

**三项决定已经确定：**

1. 《室内空间设计》以住宅为主要对象，教授可迁移的室内空间设计原理；商业空间另设课程。
2. 废弃“方框拖动 + 简单碰撞分数”作为本科实践成品的思路；采用专业二维符号、尺寸准确的家具、真实三维场景及有意义的设计情境。
3. 三维漫游和效果图应进入学习闭环，而非仅作为最后的装饰性展示。效果图必须尽可能忠实于学生实际设计的空间几何。

## 1. 试验目标与非目标

### 1.1 首要目标：验证线上实践是否能促进专业认知

要求学生不仅**做出一个方案**，还能够：

- **识别问题**：从家庭成员、生活方式、场地与限制中发现空间冲突。
- **建立关系**：理解功能分区、尺度、通行、采光、私密性、可变性之间的联系。
- **形成方案**：在现实约束下提出至少两种有实质差别的设计方案。
- **解释取舍**：说明为什么选择方案A、放弃方案B，而非单纯追求“好看”。
- **发现并修正错误**：通过模拟生活情境、观看空间视角、分析反馈修订方案。
- **迁移知识**：面对新的住宅户型或新的使用者需求时，能独立应用同一类知识。

### 1.2 次要目标：验证可推广的课程生产流程

形成可复用的“线上实践课件生产技术”——以后可用于住宅设计、商业空间、展示设计、产品设计，甚至其他具有可操作对象和可检验结果的专业课程。

应复用的是**教学任务、状态记录、反馈、评价、嵌入与交付协议**，而不是强制所有学科共用一套三维编辑器。

### 1.3 明确非目标

首期**不**开发：

- 全功能 CAD、BIM、施工图、结构和设备专业软件；
- 覆盖所有家装物品的无限制模型商城；
- 可替代教师的“审美自动评分器”；
- 一键生成完整设计方案的 AI 代做；
- 以通关积分、拖动物件数量、操作速度评定学生设计能力的小游戏；
- 尚未验证教学收益前的大而全通用课程平台。

## 2. 教学设计的硬性要求

### R1｜先有学习目标，再确定交互动作

每个实验必须明确填写：

`知识点 → 学生常见误解 → 设计任务 → 可操作变量 → 可观察结果 → 学生需要解释的原因 → 评价证据`

如果学生只需照着提示点选、拖动到预设位置就算成功，此实验判为**不合格**。

### R2｜具有本科层次的开放性与矛盾性

设计任务应有多个可辩护的方案，不能只存在唯一标准布局。引入现实冲突，例如：

- 开放式公共区域与安静、私密需求的冲突；
- 大餐桌与动线宽度、可用空间的冲突；
- 窗边办公位置与客厅采光、观景的冲突；
- 老年人夜间安全与空间布置效率的冲突；
- 收纳容量与空间通透性的冲突。

约束必须分层：**硬约束**（场地边界、禁止修改的墙体、显著阻挡或相互穿透）与**软约束**（采光偏好、距离、社交体验、灵活使用等）；不能把偏好当成规范性“对错”。

### R3｜几何模型可信、专业图形可信

二维模式应提供按真实尺寸缩放的墙体、门窗、家具及卫浴设备的专业平面符号；三维模式应有与二维数据一致的实体模型。桌椅、沙发、柜体不得仅以抽象矩形作为最终学生界面。

每个关键物件至少具备：对象ID、类别、位置、旋转、长宽高、占用边界、使用净距（用于教学提示）、材质、二维图元、三维模型引用；必要时有开启方向和操作空间。

### R4｜每次关键决策有可验证的反馈

反馈分三层，且分清性质：

1. **确定性计算**：面积、尺寸、碰撞、路径连通性、家具与门扇开启冲突、特定规则阈值。
2. **情境/启发式分析**：使用场景顺畅度、空间邻接合理性、公共活动便利性等，显示依据与局限。
3. **教师/同伴/AI评议**：审美、创意、氛围、生活方式匹配等开放判断，不能伪装为可证明的唯一正确答案。

反馈应说明“出现了什么问题、为什么可能影响使用、可以修改哪些变量”，允许学生保留不同意见并写出理由；禁止自动代替学生把设计改成标准答案。

### R5｜支持结果观察与前后对比

必须支持：二维平面、实时三维、室内第一人称视角、A/B方案同条件比较、方案迭代记录。试点还应提供至少两个固定视角的较高质量效果图。

同一方案的各个输出应具备几何一致性：家具位置、门窗位置、墙体分隔、尺寸与材料选择必须可追溯到同一份场景数据。由生成式AI提供的“氛围灵感图”须单独标识，不能混作设计成果实证。

### R6｜评价设计过程，而非只评价最终图片

需保存任务约束、原始方案、关键修改、系统反馈、学生解释、最终方案、对比结果和教师评价。学生提交物应能体现**为何修改**，而非只是截图。

### R7｜与现有视频课程解耦

可先批量制作微课视频，再挂接网页实验；交互暂停、章节切换、练习等由运行时触发，不在视频素材内部硬编码。视频可替换，实验与评价记录不受影响。

视频中可设置知识检查，但复杂空间操作放在网页工作区。AI开放式答疑可优先在阶段末或课后使用，避免每几分钟都调用LLM造成干扰和成本上升。

### R8｜适应普通学生设备与教学部署

核心功能运行于现代桌面浏览器，不要求学生有高端显卡；三维模型、贴图需分级加载。不能保证所有移动设备具备完整建模体验，手机端优先实现浏览/点评与低门槛操作。

需要有键盘可用的编辑替代（坐标/属性面板、移动、旋转、撤销），必要时提供简化2D模式与无动画降级。

## 3. 课程界面与学生体验

建议采用五区布局（具体宽度随屏幕适配）：

```text
┌────────────────────────────────────────────────────────────┐
│ 课程/章节   当前任务与学习目标   进度   保存/提交            │
├──────────┬─────────────────────────────────┬───────────────┤
│ 知识与任务│        2D / 3D 设计工作区       │ 家具/属性/检查 │
│ - 微课   │        场景编辑、漫游、视角      │ - 参数        │
│ - 情境   │        布局、家具、材料          │ - 实时反馈    │
│ - 约束   │                                 │ - 设计提示    │
├──────────┴─────────────────────────────────┴───────────────┤
│ 方案A/B   关键决策记录   设计解释   效果图   教师反馈  提交   │
└────────────────────────────────────────────────────────────┘
```

**推荐学习节奏：**

1. 阅读任务书与住户画像；确认现实约束。
2. 观看一段针对性短视频/案例，明确设计原理。
3. 独立完成初始方案，允许试错。
4. 运行指定“生活情境”，查看可复核反馈。
5. 观察三维空间并生成效果图；记录观感与问题。
6. 复制方案，做有依据的实质性调整。
7. 让A/B在同一指标与相同相机视角下比较。
8. 写简短设计论证并提交；获得教师或同伴评议。

需保留“隐藏建议/自由探索”模式，避免系统过早给出标准解，损害学生独立判断。

## 4. 第一阶段唯一推荐样板：90㎡三居室公共空间

### 4.1 为什么先选它

它能把空间、人体尺度、功能邻接、采光、生活情境与审美体验同时带进来，具有真实设计复杂度，但范围可限制在客厅—餐厅—厨房邻接区域，避免首期陷入整套住宅施工设计。

**课型：**本科环境设计专业《室内空间设计》第4—5章的实践课；建议课堂用60—90分钟，允许课后完善。

### 4.2 固定输入

- 一套**教学用示例**90㎡三居室户型（非真实住宅施工图），含尺寸、门窗、朝向、结构边界与不能修改的部分。
- 三口之家，设置“父母偶尔来住”和“居家办公”两种需求变化。
- 固定厨房管井/主要开口等适合课程阶段的约束。任何可修改墙体应标注是否为教学假设。
- 基础家具库：沙发、茶几、电视/收纳柜、餐桌椅、办公桌、边柜、灯具等（以正确尺寸为先，不追求数量）。
- 设计任务中提供可选预算档位，但首版可以只做定性成本分级，不虚构精确造价。

### 4.3 学生必须完成的五项决策

1. 公共区域的功能分区与主要活动中心；
2. 餐厅与厨房的关系及家庭成员活动路线；
3. 主要家具的尺度、朝向、间距与布局；
4. 工作、会客、家庭休闲等使用情境的兼容；
5. 至少一种替代方案及取舍论证。

### 4.4 至少运行的三类情境

| 情境 | 学生观察什么 | 引导讨论 |
|---|---|---|
| 日常家庭晚餐 | 厨房至餐桌路径、多人落座/走动的空间冲突 | 路径更短是否一定更好？ |
| 周末会客 | 座位关系、视线、公共活动空间、经过流线 | 交流性与通达性如何平衡？ |
| 家庭成员临时办公 | 桌面位置、采光、背景干扰、动静分区 | 共享空间应牺牲哪些体验？ |

情境不是要求首期引入复杂人物动画；最初可用**路径线、占用区域、第一人称视点与标注**表达，先验证学生是否能认知问题，再决定是否制作真实人物动画。

### 4.5 提交成果

- 2D平面图（带必要尺度与图例）；
- 3D方案及两个固定视角效果图；
- 方案A、方案B（至少一个实质性布局差异）；
- 情境检查报告（硬事实/启发式观点分开）；
- 设计说明：需求—决策—问题—修改—最终取舍；
- 可重播的场景数据及关键版本记录。

### 4.6 不把学生锁在“标准答案”

禁止出现“规定沙发必须放在东墙”“餐桌必须放在厨房旁”式的唯一解。系统只对明确可计算的问题给确定结论；其余要求学生**比较并论证**。教师应可批准“有充分理由的非常规方案”。

## 5. 效果图如何纳入教学

采用**三级可视化**，避免把成本最高的渲染放在每次拖动后。

| 层级 | 技术形态 | 触发时机 | 教学目的 |
|---|---|---|---|
| L1 即时观察 | 浏览器实时三维（WebGL） | 编辑过程中随时 | 理解尺寸、空间关系、遮挡、视线 |
| L2 教学截图 | 统一相机与基础灯光渲染 | 保存关键方案时 | 在相同条件下比较方案A/B |
| L3 高质量效果图 | 后台三维渲染，可按需调用 | 阶段末/作业提交 | 分析光影、材料、氛围及视觉效果 |

**实现原则：**

- 保持单一权威场景模型（single source of truth），2D/3D/导出/渲染共享对象标识与变换参数。
- 同一个相机位置、镜头参数、时间/灯光预设可重复生成，保证方案对比公平。
- 高质量渲染建议评估Blender离屏渲染；须实测吞吐、显存、内存、排队与成本。
- 生成式AI仅作为可选“风格探索参考”；如用于美化照片，应明确标识为概念图并做几何一致性检查。
- 学生仍需解释色彩、采光、材质为何适配使用情境；漂亮的渲染图**不直接等于高分**。

## 6. 评分与反馈机制

### 6.1 推荐试点评分量表（可供教师调整）

| 维度 | 参考权重 | 评分依据 |
|---|---:|---|
| 需求理解与问题界定 | 20% | 是否分析住户与情境，是否识别空间冲突 |
| 空间组织与尺度 | 25% | 分区、通行、家具尺度、可解释的功能关系 |
| 情境分析与修正 | 20% | 是否发现问题、是否有针对性修改 |
| 方案比较与论证 | 20% | 至少两方案的真实差异与取舍依据 |
| 空间表达与完成度 | 15% | 2D/3D一致性、说明清晰度、视觉表达 |

这是一份**试点量表草案**，不是普遍适用的专业评分标准，应由任课教师校准。

### 6.2 系统自动分析的责任边界

- **可自动判定**：明显几何穿透、墙/门/家具冲突、计算面积、路径连通性、部分可配置净距检查。
- **可辅助分析**：采光倾向、交通便捷性、工作与会客的干扰、家具尺度舒适度——结果需附模型和假设。
- **不可武断判定**：美感、文化表达、创意价值、复杂家庭关系下的“最佳”设计。

与无障碍、安全、防火有关的规则必须标注**规范版本、适用条件、教学简化程度**；不能把简化模拟当成正式合规审查。

### 6.3 AI评议的角色

AI可读取**学生设计状态的结构化摘要 + 相关检查结果 + 方案说明**，提出追问、反例、方案比较建议；不得虚构模型中不存在的房间、门窗及空间数据。AI评价可由学生选择查看，教师保留最终评价权。

推荐的问题形式：

> “你把办公桌设在客餐厅交界处，晚餐时其他人的活动可能怎样干扰工作？请在方案B中解决这一冲突，并说明牺牲了什么。”

而不是：

> “正确答案是把桌子放到窗边。请拖动到指定位置。”

## 7. 技术体系：复用成熟空间编辑器，重点建设教学层

### 7.1 原则性架构

```text
教学编排层（课程、任务、情境、目标、微课关联）
                  │
学习状态与证据层（方案、版本、论证、反馈、评价）
                  │
可复用实践协议（加载任务 → 交互状态 → 检查 → 提交）
                  │
课程领域插件：住宅空间设计
 ├─ 场景数据模型 / 专业编辑器适配
 ├─ 专业二维符号、家具及三维资产
 ├─ 约束检查与生活情境
 ├─ 2D/3D交互、漫游、A/B比较
 └─ 高质量渲染适配器
                  │
统一认证、资源管理、成绩与现有学习平台接口
```

**不要为所有学科强行抽象“通用三维仿真内核”。** 先固定课程任务/证据协议，让专业引擎作为可替换适配器。

### 7.2 候选技术与采用策略

| 模块 | 首选调研方向 | 选择理由 | 开发前必须确认 |
|---|---|---|---|
| 2D/3D专业编辑 | [OpenPlan3D](https://github.com/laanlabs/openPlan3D) | 网页平面编辑、家具库、3D和漫游可复用 | 模型尺寸/格式、嵌入方式、API改造成本、性能及许可 |
| 3D运行时 | [Three.js](https://threejs.org/) | 浏览器三维、glTF模型支持 | 是否需要额外自行维护场景同步逻辑 |
| 家具资产 | 自建精选合法授权 GLB/glTF 资产集合 | 专业外形与尺寸真实 | 模型与纹理再分发许可、归属、性能、比例与LOD |
| 高质量效果图 | [Blender后台渲染](https://docs.blender.org/manual/en/5.1/advanced/command_line/render.html) | 从真实三维数据输出较高质量图像 | 场景导出一致性、摄像机重建、队列和服务器成本 |
| 课程集成 | 自有 LMS API 或 [LTI 1.3](https://www.1edtech.org/standards/lti) | 复用学校账号、课程上下文、成绩 | 现有平台是否支持及支持到什么程度 |

上述均是**候选**而非已经完成适配。开源项目代码许可证与家具/贴图库许可证是不同的事情，必须分别核对。

### 7.4 行为证据协议（示意）

```text
LessonSpec: 学习目标、内容资源、实验任务、前置条件
TaskSpec: 场地/人物/限制/情境/评价维度
SceneState: 可恢复的专业设计状态
DecisionEvent: 学生做了哪类实质性设计修改
CheckResult: 哪个规则/情境的结果及依据
Reflection: 学生为何修改，如何看待取舍
Submission: 带版本的场景、图像、说明与评价
```

记录有助于教学分析的关键动作即可，不必连续录制屏幕或逐像素追踪；涉及学生身份和作业的保存、保留与删除须符合学校要求。

### 7.5 平台嵌入与交互

- **独立开发、后集成**：试点可以在独立子站运行，验证成功后再对接现有平台。
- 优先评估 LMS 的自有 API；若其支持 LTI 1.3，可利用标准方式实现登录、课程上下文与成绩回传。
- 嵌入形式优先可控的新标签页/独立应用；若采用 iframe，提前验证登录态、跨域、第三方Cookie与全屏/三维操作限制。
- 视频使用现有生产系统，视频资源ID和实验任务ID解耦；运行时负责时间点暂停、任务启动及实验完成后返回进度。
- 学生方案要能自动保存、显式导出，并由老师打开回放与评分。

## 8. 分阶段实施：先证明课程价值，再扩建工具

### 阶段0：教学样板设计与开源技术审计

**工作：**任课教师确认学习目标与生活场景；Agent对OpenPlan3D及备选实现做源码级调研、依赖与资产许可证审计、样机性能测试；输出概念原型而非大规模开发。

**交付：**

- 完整实验任务书与学生画像、固定户型数据；
- `TECH_SPIKE_REPORT.md`（编辑器改造方案、资产库、导出可行性、设备表现、风险）；
- 不少于两个候选实现路径的成本/风险比较（在现有开源项目上扩展 vs 自建有限功能模块）；
- 教师认可的课程评价量表草案。

**通过门：**能证明选定编辑器可以在固定住宅中维护真实尺寸家具、读取/保存场景、二维三维一致、插入课程外部情境；否则不进入下一阶段。

### 阶段1：完整教学竖切样板（MVP）

**必须做到：**

- 一个可运行的90㎡固定住宅示例与公共区设计任务；
- 专业二维平面、精选家具模型、3D同步与第一人称漫游；
- 三个情境里至少两个具有可执行的空间检查；
- A/B方案复制与差异比较；
- 学生“设计理由—收到的反馈—修改理由”记录；
- 两张相同摄影机预设的截图或效果图（首轮可先用实时引擎出图，后台高质量渲染作为独立技术验证）；
- 教师查看提交包与评分表。

**通过门：**不是“能摆家具”，而是学生可以独立完成任务、主动发现冲突、修订并解释至少一项关键设计决定。

### 阶段2：真实课堂小规模试验

建议找**8–15名**目标年级学生先进行可用性与认知试点（人数仅为可操作的试点建议，不作统计代表性保证）；教师现场观察，不让研发团队不断提示正确答案。

收集：

- 任务前/后的情境判断题与迁移小题；
- 是否能区分硬约束与方案偏好；
- 是否出现了有理由的A/B差异；
- 修改说明是否从“好看/不顺眼”上升到空间关系与使用者需求；
- 完成时间、遇到的编辑阻碍、浏览器性能与渲染情况；
- 学生和教师对实际教学价值的反馈。

如条件允许，后续开展更完整的课堂对照：**同样内容**分别采用视频+图纸练习与视频+交互实践，比较独立设计和知识迁移表现。不能仅以学生“觉得好玩”作为有效性证据。

### 阶段3：优化后推广

先从住宅公共区扩展到卧室、厨房、卫生间、采光/照明、材料与收纳等课程实验。只有当多个住宅实验复用了相同的任务/证据/评价接口，才考虑推广到《商业空间设计》等其他学科。

## 9. 验收门禁与停止条件

| Gate | 必须验证 | 失败处理 |
|---|---|---|
| G0 教学真实性 | 任务有真实使用者冲突、至少两条可辩护方案路径 | 教师重写任务，不继续堆交互按钮 |
| G1 结构与尺寸 | 平面数据、物件模型、三维尺寸相互对应；固定结构不可被随意修改 | 修复场景契约 |
| G2 反馈可信 | 自动规则可复算，能显示依据；评价不把主观偏好伪装成事实 | 缩减不可信反馈 |
| G3 视觉一致 | A/B相同相机条件，渲染内容与真实场景一致 | 暂停高质量渲染，先修同步 |
| G4 作业完整 | 保存、重新打开、版本对比、提交、教师查看可闭环 | 禁止进入实课试点 |
| G5 设备可用 | 主流普通教学电脑可完成任务，有基本降级路径 | 压缩资产、优化体验 |
| G6 教学实效 | 学生能解释方案选择、发现问题并将知识用于新情境 | 重做教学设计，不以增加动画掩盖失败 |
| G7 可复制性 | 新增同类实验无需复制整套编辑器及评价系统 | 重构领域任务配置与接口 |

**项目可以在G6失败时暂停扩张。** 验证“网页实践并未明显帮助专业认知”也是有效的试验结论，不应靠增加3D视觉炫技来制造成功感。

## 11. 关键风险及应对

| 风险 | 应对 |
|---|---|
| 编辑器功能强但不适于教学嵌入 | 尽早验证场景API、权限与代码可改造性；保留替换适配器路径 |
| 过多模型拖慢学生电脑 | 限定精选模型、尺寸校验、LOD/压缩贴图、2D降级 |
| 三维渲染精美但与学生方案不一致 | 一份场景源数据；固定相机与模型引用；自动差异检查 |
| 自动评分过度简化设计 | 定量事实/启发式/教师判断三层分离 |
| 反馈过多造成答案诱导 | 延迟提示、可关闭提示、保留独立尝试阶段 |
| 开源库与家具素材版权混淆 | 代码与资产分别审计、保留 attribution/licence 清单 |
| 大量视频与实验内容耦合 | 微课单独管理，以任务/章节ID链接实验 |
| 学生作业遗失或无法复核 | 自动保存、可恢复版本、导出与教师回放测试 |
| 有趣却没有认知收益 | 用迁移任务、方案解释和课堂对照评估；失败即调整目标 |

## 12. 成功标准与决策原则

**第一阶段成功**并不意味着完成了一套华丽的“虚拟装修平台”，而是至少有一节课证明：

1. 学生面对开放住宅问题时能主动设计，而不是执行预设答案；
2. 家具、墙、门窗、空间和三维呈现可信，交互不妨碍认知；
3. 学生能通过情境与效果反馈发现初始设计的某个真实问题；
4. 学生能给出修改理由，并在A/B中展示不同取舍；
5. 教师能基于完整学习证据进行评价；
6. 这套教学闭环具有向其他实践课程推广的潜力。

**最终决策原则：先证明教学有效，再优化视觉效果；先做完整的一节课，再做完整的一门课；先形成可复用的教学协议，再建设通用平台。**
